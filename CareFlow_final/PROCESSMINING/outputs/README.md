# CareFlow – Member 3 – Directly-Follows Graph

## Day 8 Task

**Task:** Generate DFG  
**Commit:** `feat: generate directly follows graph`

This module takes the normalized event log produced by **Member 2** and uses **PM4Py** to generate a Directly-Follows Graph (DFG).

## Input

Place Member 2's file here:

```text
PROCESSMINING/
└── int_normalized_event_log.csv
```

The script expects these logical fields:

- `Case_ID`
- `Activity`
- `Timestamp`

The script is case-insensitive for these column names.

## Files

```text
PROCESSMINING/
├── int_normalized_event_log.csv       # Member 2 input
├── generate_dfg.py                    # Member 3 main file
├── validate_dfg.py                    # DFG validation
├── DFG_README.md
└── outputs/
    ├── directly_follows_graph.png    # Generated by PM4Py
    └── dfg_edges.csv                 # Generated DFG transitions
```

## Install

If PM4Py is already installed from the earlier project setup, no new installation is required.

Otherwise:

```bash
pip install pm4py pandas
```

Graph visualization may also require Graphviz on the system.

## Run

From the `PROCESSMINING` directory:

```bash
python generate_dfg.py
```

Then validate:

```bash
python validate_dfg.py
```

## DFG Meaning

For example:

```text
Registration → Triage
Triage → Doctor Consultation
Doctor Consultation → X-Ray
X-Ray → Discharge
```

Each arrow represents that one activity was directly followed by another activity within a patient case.

`dfg_edges.csv` contains:

```text
Source_Activity,Target_Activity,Frequency
```

The `Frequency` column shows how many times that transition occurred across the event log.
