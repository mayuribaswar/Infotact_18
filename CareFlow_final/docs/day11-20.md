# Day 11 – Intermediate Layer Preparation

## Objective

The objective of Day 11 was to prepare the Intermediate layer for detailed healthcare process analysis.

## Work Completed

The raw healthcare event data was transformed into intermediate-level models.

The Intermediate layer was designed to provide:

* Patient-level process information
* Ordered patient activities
* Activity sequences
* Event-to-event relationships
* Process transition information

## Models

```text
models/
└── intermediate/
    ├── int_patient_process.sql
    └── int_activity_transitions.sql
```

### `int_patient_process`

This model organizes events for each patient in chronological order and provides information required for patient journey analysis.

### `int_activity_transitions`

This model identifies transitions between consecutive healthcare activities.

Example:

```text
Registration → Consultation
Consultation → Diagnosis
Diagnosis → Treatment
Treatment → Discharge
```

## Outcome

The Intermediate layer was successfully prepared for downstream MART models.

**Status: Completed ✅**

# Day 12 – Activity Transition Generation

## Objective

The objective of Day 12 was to generate activity transition pairs from the patient event sequence.

## Work Completed

The activity sequence of each patient was analyzed using SQL window functions.

Functions such as:

```sql
LAG()
LEAD()
ROW_NUMBER()
```

were used to determine the previous and next activities.

## Transition Example

```text
Activity A → Activity B
Activity B → Activity C
Activity C → Activity D
```

These transitions help identify how patients move through different healthcare activities.

## Model

```text
models/
└── intermediate/
    └── int_activity_transitions.sql
```

## Analysis Enabled

The transition model supports:

* Process flow analysis
* Activity sequence analysis
* Waiting-time analysis
* Bottleneck identification
* Rework detection

**Status: Completed ✅**
